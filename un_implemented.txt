Tracey Compiler — Unimplemented / Deferred Core Language Features
=================================================================

This document lists core language features (excluding the standard library
in lib/) that are not yet implemented in the Tracey compiler, as verified
against include/tracey/*.h and general/{lexer,parser,semantic,codegen,preprocessor,assembler}/*.c.

1. Lexer
-------
- Hexadecimal / binary integer *values*: the lexer recognises 0x/0X and
  0b/0B prefixes, but the parser decodes decimal only, so these literals
  are not usable yet.
- Integer suffixes (u, l, ul, ll) are not implemented.
- Character literals wider than one byte / multi-char constants.
- Increment / decrement operators (++ and --).
- Bitwise complement for non-integer types (~ applies to integer operands
  only; mvn encoding is missing from the assembler, temporarily returns 0).
- Compound assignment for bitwise ops is lexed/parsed but codegen uses
  load-modify-store for all compound assignments.

2. Parser / Grammar
------------------
- Question-mark / colon ternary is implemented and right-associative.
- Shift operators (<<, >>) are lexed but have no parser precedence level
  and are not usable in expressions yet.
- Any statement or expression forms not listed in the implemented grammar:
  no do-while, no switch, no try/catch, no foreach/range-for.

3. Types
-------
- No struct / union / enum types.
- No typedef / type aliases.
- No function pointer types.
- No variable-length arrays; only fixed-size arrays that decay to pointers.
- long vs long long: both 64-bit on AArch64 LP64 but distinct types;
  implicit conversion allowed but not formally specified.

4. Statements
------------
- No switch statement.
- No do-while loop.
- goto: forward-only restriction is NOT statically enforced; labels are
  validated as declared/used per function, but direction (forward vs
  backward) is not checked.
- break / continue: stack is NOT cleared on error paths; an error inside
  a loop may leave stale break/continue targets on the codegen stacks.

5. Expressions
-------------
- No compound literals, no designated initializers.
- No typeof / decltype.
- No sizeof operator as an expression (size_t is a type keyword but
  sizeof is not implemented).

6. Semantic / Type Checking
--------------------------
- No generic / _Generic selection.
- No const / volatile / restrict qualifiers on types.
- No strict aliasing rules.
- No implicit narrowing diagnostics beyond basic assignability;
  float-to-int and long-to-int conversions are permitted without error.

7. Preprocessor
--------------
- #if expression support is minimal: defined(NAME) or integer constants
  only; macro names are not expanded, and there is no #else/#elif.
- #ifndef GCC / #defined cross-compiler macro semantics are partially
  implemented (#defined NAME defines NAME=1 only if a host builtin such
  as __GNUC__ is present) but need full host-compiler integration.
- No #error / #warning directives.
- No #undef directive.
- No macro token-pasting (##) or stringification (#).
- Function-like macros accept several parameters syntactically, but only
  the first parameter is substituted during expansion.
- No variadic macros (... / __VA_ARGS__).

8. Code Generation (AArch64 Linux)
---------------------------------
- Target is AArch64 only; no x86_64, RISC-V, or other backends.
- No optimization passes (no dead-code elimination, no constant folding
  at codegen time, no register allocation beyond stack temporaries).
- Calls with more than 8 arguments are not supported (x0..x7 only).
- Assembler missing encodings:
    * lsl (logical shift left) — not supported.
    * lsr / asr (logical / arithmetic shift right) — not supported.
    * mvn (bitwise not move) — bitwise NOT currently emits mov x0,#0.
  eor (exclusive OR) IS implemented (0xCA000000 base).
- No stack canaries, no ASLR/Pie considerations, no unwind tables
  (.cfi_*) emitted.
- No support for tail calls.

9. Build / Driver
-----------------
- No debugger information (-g / DWARF) emission.
- No link-time optimization.
- No incremental / dependency-based rebuild beyond #include visited-set
  guarding.

Note: The standard library (lib/stdio.htrc, lib/stdio.trc) provides only
the builtins print, printf, input_int, input_str and is documented
separately; it is out of scope for this core-language list.
